# Contributing to Neutral

Thank you for helping build the Neutral ecosystem. The projects are at an early
stage, so clear problem descriptions and small, focused changes are especially
valuable.

## Before contributing

1. Read the target repository's README, contribution guide, and license.
2. Search existing issues and pull requests for related work.
3. For a substantial feature or architectural change, open an issue before
   implementation so the scope and direction can be discussed.

Instructions in a project repository take precedence over this organization-wide
guide.

## Issues

When reporting a bug, include:

- the affected project and revision or version, if known;
- the operating system, architecture, and relevant tool versions;
- a minimal reproduction;
- expected and actual behavior; and
- complete error output with secrets and personal data removed.

Use the security process in [`SECURITY.md`](SECURITY.md) for vulnerabilities. Do
not disclose security-sensitive details in a public issue.

Feature proposals should explain the problem first, describe the intended users,
and note reasonable alternatives. A proposal is not a commitment to implement or
accept a feature.

## Pull requests

- Keep each pull request focused on one coherent change.
- Add or update tests when behavior changes.
- Update documentation for user-visible changes.
- Follow the formatting and validation commands documented by the project.
- Explain design choices and known limitations in the pull request description.
- Avoid unrelated refactors or generated-file churn.

By submitting a contribution, you agree that it may be distributed under the
license of the repository to which you contribute and that you have the right to
submit it.

All participation is governed by the [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md).
